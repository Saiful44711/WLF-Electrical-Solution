৩. শুরু করার আগে

  1. বর্তমান GitHub repository → Code → Download ZIP আলাদা রেখে দিন। এই package-এ original snapshot-ও আছে।
  2. আপনার বর্তমান Supabase database-এর আলাদা owner-controlled backup থাকলে সংরক্ষণ করুন। এই নতুন support backup পূর্ণ Auth/schema/settings recovery backup নয়।
  3. কম ব্যবহার হয় এমন সময়ে SQL ও frontend update পরপর করুন। SQL চলাকালে খুব অল্প সময় schema locks লাগতে পারে। কোনো script দিয়ে live data reset করবেন না।
  4. চলমান app-এর login, একটি calculation result, components count, troubleshooting count, request count note/screenshot রাখুন। কোনো password/token screenshot করবেন না।

Existing project-এ 01_SETUP.sql, seed.sql বা 02_FIRST_SUPER_ADMIN.sql চালাবেন না। শুধু নিচের UPDATE_V210.sql চালাবেন।

৪. Supabase SQL update

  1. Supabase project খুলুন → SQL Editor → New query।
  2. GitHub-Update/supabase/UPDATE_V210.sql Notepad-এ খুলে পুরো code paste করুন। Owner/postgres হিসেবে Run দিন। এটি নতুন tables/functions/policies যোগ করে; reference data reseed করে না।
  3. Success হলে আরেকটি query-তে VERIFY_V210.sql চালান। Browser maintenance privilege false, service maintenance এবং Edge profile read true, সব public wlf tables-এর RLS true হবে।
  4. Update পুনরায় চালালেও default categories reset হবে না এবং পুরোনো reference data থাকবে। SQL error হলে frontend upload-এর আগে error text জানান।

wlf_private schema কখনো API Settings-এর exposed schemas-এ যোগ করবেন না।

৫. নতুন Edge Function deploy

  1. Supabase → Edge Functions → Deploy a new function → Via Editor। নাম দিন wlf-maintenance।
  2. GitHub-Update/supabase/functions/wlf-maintenance/index.ts-এর পুরো code Editor-এ paste করে Deploy করুন। Existing wlf-admin reset-password function পরিবর্তন করবেন না।
  3. নতুন function-এর Settings-এ Verify JWT with legacy secret = OFF করে Save করুন। Handler নিজে Supabase Auth token ও current approved Super Admin profile যাচাই করে।
  4. Supabase-এর server environment-এ default secret key/service role available থাকতে হবে। SQL update service_role-কে শুধু profile read ও maintenance function execute দিয়েছে। Service key GitHub/frontend-এ দেবেন না।
  5. Google Drive secrets পরের section অনুযায়ী দিন। Drive setup ছাড়া storage meter/documents/user search চলবে; backup action Drive setup চাইবে।

৯. Backup ও clear ঠিক কী করে

  • Start-এ selected request IDs freeze হয়। 25 request করে separate part upload হয়। প্রতিটি part-এ full request/form snapshot, সব history ও idempotency operations থাকে। 150-history display limit export-এ প্রযোজ্য নয়।
  • সব parts Google Drive-এ upload, পুনরায় download এবং SHA-256 verify হওয়ার আগে clear চালানো যায় না। একটি part fail হলে resume করুন; verified parts repeat upload হয় না। Retry-তে অসম্পূর্ণ part-এর orphan Drive file থাকতে পারে; verified history দেখে পরে নিজে tidy করবেন।
  • Clear-এর সময় Drive file আবার hash-check হয়। একই backup-এর এখনো Solved এবং অপরিবর্তিত records ছোট transaction batch-এ permanent delete হয়। Unsolved, নতুন, edited records রাখা হয়। Notification badge শুধু unsolved records গণনা করে।
  • কয়েকটি batch clear হওয়ার পরে network বন্ধ হলে আগে cleared batch থাকে; তাদের verified Drive backup আছে। একই backup resume করলে clear পুনরায় duplicate হবে না।
  • Backup with Clear আগে backup করে, তারপর আলাদা confirmation চায়। “70% full” শুধু সতর্কবার্তা, automatic delete নয়। SA login এবং app খোলা/visible থাকলে 15 মিনিট অন্তর warning check হয়; app বন্ধ থাকলে push alert নেই।
  • পুরোনো requests clear হলে old live reports ও R&I performance-এ সেগুলো আর গণনা হবে না। এই version মাসভিত্তিক historical aggregate সংরক্ষণ করে না; আগে report export করুন অথবা backup restore করুন।
  • Postgres delete-এর পরে autovacuum জায়গা reusable করে; used MB সঙ্গে সঙ্গে কমবে বা পুরো database শূন্য হবে—এমন প্রতিশ্রুতি নেই। কোনো blocking VACUUM FULL স্বয়ংক্রিয়ভাবে চালানো হয় না।
  • Backup journal, operation tombstones ও users/settings এখনও অল্প জায়গা নেবে। Indefinite unlimited free storage guarantee নেই। Largest tables দেখে পর্যবেক্ষণ করুন।

১০. Restore ও document permissions

Restore support backup part → একটি JSON part নির্বাচন → review/confirm। Multipart backup হলে প্রতিটি part আলাদা import করুন। শুধু একই Supabase project-এ restore; missing request IDs insert হয়, existing IDs overwrite হয় না। Related users/forms থাকতে হবে; validation/FK error হলে সেই part rollback হবে। Auth passwords, entire schema, Google files, project settings restore হয় না।

Documents Links-এ file upload হয় না। শুধু category/name/link/extra fields Postgres-এ থাকে। Drive-এর original file private থাকলে সংশ্লিষ্ট account-কে access দিন। Viewer download permission বন্ধ থাকলে app তা bypass করবে না। App-এর link delete করলে Drive file থাকবে। Google backup OAuth authorization ও shared document permissions দুটি আলাদা বিষয়।
