QMS-এ Paid feature information: deployment নির্দেশিকা

QMS Input-এ Paid feature chip, QMS output-এ নতুন Table 7, Other components-এ Select all, আর সব backup ও Excel-এ নতুন ডেটা।

কী বদলেছে (v2.6.5)

  • QMS Input → "6 · Paid feature information": লিফটের Control system (MOT / NICE3000+) অনুযায়ী chip আসে: Voice Announcer, Access Controller (৩ ধরন), RFID Card, Cloud Monitoring, Remote Alarm, BMS, Regenerative drive। একাধিক chip বাছা যায়, কোনোটাই বাধ্যতামূলক নয়।
  • Output → "7 · Paid feature information": যে chip বাছবেন তার সব সারি আসে (যেমন MOT-এ Remote Alarm = ৪ সারি)। কলাম: Category, Item code, Item name, Spec, Brand, Supplier, Price।
  • Regenerative drive: একটাই chip। NICE3000+ হলে ভেতরে kW বাছাই (5/7/11/15/18/22/30), না বাছলে Save হবে না। MOT-এ একটাই (RGN-B06), তাই বাছাই নেই।
  • Special note (ঐচ্ছিক): Paid feature অংশের নিচে, সর্বোচ্চ ৫০০ অক্ষর; Table 7-এর নিচে দেখায়।
  • Other components: আগের মতো একটা একটা টিক, সঙ্গে Select all ও Clear all বাটন।
  • Backup ও Excel: Table 7 ও note আছে লিফটের Excel রিপোর্টে (এক শিট), একাধিক লিফটের QMS Output Tables শিটে, QMS Lifts শিটে (নতুন কলাম "Paid feature note"), QMS Components শিটে (Section = Paid feature), QMS JSON backup/restore, Excel backup ও পূর্ণ backup/restore-এ।

বিষয়অনুমান
ডেটা কোথায়Hardware Catalogue-এ প্রতি system-এর নিচে নতুন model Paid feature। আপনার workbook থেকে SQL দিয়ে ভরা; Super Admin পরে Catalogue-এই দাম/কোড বদলাতে পারবেন।
Chip তালিকালিফটের Control system-এর Paid feature-এর group অনুযায়ী। Control system না বাছা পর্যন্ত chip আসে না।
Item code না থাকলে"no code" দেখায় (NICE3000+-এর বেশিরভাগ সারিতে code/নাম/দাম workbook-এ ছিল না, তাই ফাঁকা থাকবে)।
NICE3000+ Remote AlarmWorkbook-এ ৪টা একই রকম (শুধু MONARCH) সারি, তাই ৪টাই seed করেছি। নাম পেলে Catalogue-এ বসাবেন।
BMSWorkbook-এ কোনো ডেটা নেই; chip আছে, output-এ শুধু "BMS" সারি (code ফাঁকা)।
বানান"Cloude Monitoring" → "Cloud Monitoring" করেছি।
পুরোনো লিফটPaid feature ফাঁকা, note ফাঁকা; Table 7 এ "No paid feature was selected."
Kw-এর সারিSpec কলামে kW রাখা; একই category-তে আলাদা Spec থাকলে একটা বাছতে হয়, নয়তো সব সারি output-এ যায়।

১. Supabase SQL (একটাই)

  1. Supabase → SQL Editor → New query।
  2. প্যাকেজের UPDATE_V265.sql খুলে Ctrl+A, Ctrl+C; Editor-এ পেস্ট; Run। RLS বার্তা এলে Run without RLS।
  3. ফলাফলে mot_paid_rows = 12, nice_paid_rows = 18, paid_note_ready = true, v265_ready = true থাকা উচিত।
V264 না চালিয়ে V265 চালালে "Run UPDATE_V264.sql first" আসবে ও কিছু বদলাবে না। দুবার চালালেও সারি দ্বিগুণ হয় না।

২. Edge Function wlf-maintenance আবার deploy

Excel backup-এ Table 7 ও note এই ফাংশন বানায়।

  1. Supabase → Edge Functions → wlf-maintenance → Code; index.ts নির্বাচিত।
  2. কোড বক্সে ক্লিক করে Ctrl+A, Delete।
  3. প্যাকেজের edge-function/wlf-maintenance/index.ts Notepad-এ খুলে Ctrl+A, Ctrl+C; বক্সে Ctrl+V।
  4. Deploy updates; "Successfully deployed" পর্যন্ত অপেক্ষা। Verify JWT OFF থাকতে হবে।
ক্রম: SQL আগে, Edge Function পরে, সবশেষে GitHub।

৩. GitHub-এ আপলোড

  1. WLF-GitHub-v2.6.5-UPLOAD.zip extract করে ভেতরের ফোল্ডারে ঢুকুন।
  2. GitHub রিপো → Add file → Upload files → ভেতরের সব (Ctrl+A) টেনে দিন।
  3. Commit message: v2.6.5 QMS paid feature information → Commit changes।
  4. Actions-এ সবুজ ✓ পর্যন্ত অপেক্ষা। লাল হলে "FAILURE SUMMARY"-র নিচের লেখার স্ক্রিনশট দিন।

  3. Other components-এ Select all / Clear all চেপে দেখুন।
