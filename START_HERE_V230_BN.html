  • SUPPORT USER ফিল্টার: আগের "Assigned to"-এর জায়গায়। টিমের section-এর ইউজার তালিকা থেকে বেছে, তাদের রিকোয়েস্ট ফিল্টার করা যায়।

২. Supabase-এ ডাটাবেস আপডেট

  1. Supabase-এ লগইন করে WLF প্রজেক্ট খুলুন।
  2. বাঁ মেনু → SQL Editor → New query।
  3. Supabase প্যাকেজের UPDATE_SECTIONS_V230.sql Notepad-এ খুলুন। Ctrl+A চেপে সব বাছুন, Ctrl+C দিয়ে কপি করুন।
  4. SQL Editor-এ পেস্ট করে Run চাপুন। কোনো সতর্কবার্তা এলে Run this query বাছুন।
  5. নিচে এক সারির ফলাফল আসবে। পাঁচটা কলামই true হতে হবে:
    কলামমানে
    profile_id_section_readyপ্রোফাইলে ID আর Section যোগ হয়েছে
    admin_role_removedপুরনো Admin role নেই
    support_forms_split৬টি সাপোর্ট ফর্মে Name আর ID আলাদা হয়েছে
    ri_forms_splitR&I Activity ফর্মগুলোতেও আলাদা হয়েছে
    super_admin_profile_readyআপনার প্রোফাইলে Md. Saiful Islam, 44711, R&I Electrical বসেছে
পুরো SQL একটাই transaction-এ চলে। মাঝপথে error হলে কিছুই বদলায় না, তাই ঠিক করে আবার চালানো নিরাপদ। দুবার চালালেও কোনো ক্ষতি নেই।
যদি super_admin_profile_ready = false আসে, তার মানে Super Admin অ্যাকাউন্টের ইমেইল liftrndelectrical@gmail.com নয়। বাকি সব ঠিক থাকলে এগিয়ে যান, পরে User Management থেকে নিজের Name, ID আর Section দিয়ে দিতে পারবেন। অথবা স্ক্রিনশট আমাকে দিন।

৩. GitHub-এ ফাইল আপলোড

  1. কম্পিউটারে WLF-GitHub-v2.3.0.zip extract করুন। ভেতরে WLF-Electrical-Solution-main ফোল্ডার পাবেন।
  2. ব্রাউজারে (Chrome বা Edge) GitHub-এ আপনার WLF-Electrical-Solution repo খুলুন। উপরে branch main আছে কি না দেখে নিন।
  3. Add file → Upload files।
  4. WLF-Electrical-Solution-main ফোল্ডারের ভেতরে ঢুকুন। Ctrl+A দিয়ে সব ফাইল ও ফোল্ডার বাছুন (.github, web, shared, supabase, tests, dist ইত্যাদি), তারপর টেনে GitHub-এর আপলোড পেজে ছেড়ে দিন। GitHub একই নামের ফাইল বদলে দেবে আর ফোল্ডারের গঠন ঠিক রাখবে।
  5. আপলোড শেষ হলে নিচে Commit message দিন: v2.3.0 Sections, Name & ID update।
  6. Commit directly to the main branch বাছাই থাকা অবস্থায় Commit changes চাপুন।
  7. উপরের Actions ট্যাবে যান। Deploy WLF PWA to GitHub Pages চলতে দেখবেন (হলুদ বৃত্ত)। এটা build, সব টেস্ট আর ব্রাউজার টেস্ট চালায়, ১০–১৫ মিনিট লাগতে পারে।
  8. সবুজ ✓ এলে সাইট আপডেট হয়ে গেছে। লাল ✗ এলে ক্লিক করে যে ধাপটা লাল, তার স্ক্রিনশট আমাকে দিন। লাল হলে সাইট বদলায় না, আগের ভার্সন চালু থাকে।
শুধু বদলানো ফাইল আপলোড করতে চাইলে নিচের ফাইল তালিকা দেখুন। তবে পুরো ফোল্ডার আপলোড করাই সহজ আর নিরাপদ।

৫. (ঐচ্ছিক) পুরনো ইউজার ও টেস্ট রেকর্ড মোছা

এটা আর ফেরানো যায় না। আগে ধাপ ১-এর মতো আবার নতুন ব্যাকআপ নিন।

যা মুছবে: Super Admin ছাড়া সব ইউজার (লগইন ও প্রোফাইল), আর সব টেস্ট রেকর্ড: সাপোর্ট রিকোয়েস্ট ও ইতিহাস, R&I Activity ও Project, Damage Demand, QMS, usage log, সেভ করা হিসাব। আপনার নিজের টেস্ট রিকোয়েস্টও মুছবে।
যা থাকবে: আপনার লগইন, পাসওয়ার্ড ও অনুমতি; Components data, Troubleshooting, সাপোর্ট ফর্ম, Documents links, R&I ক্যাটাগরি, সেটিং।

  1. SQL Editor → New query → CLEANUP_KEEP_SUPER_ADMIN_V230.sql পুরোটা পেস্ট → Run।
  2. ফলাফলে profiles_left = 1 আর support_requests_left = 0 হলে কাজ শেষ।
  3. note-এ যদি লেখা থাকে "Login accounts could not be deleted here", তাহলে বাঁ মেনু → Authentication → Users-এ গিয়ে আপনার ইমেইল ছাড়া বাকিগুলো বেছে Delete করুন। তাদের অ্যাপে ঢোকার পথ আগেই বন্ধ হয়ে গেছে।

৬. নতুন ইউজার approve করা

  1. ইউজার Request access দিলে User Management-এ Pending দেখাবে।
  2. খুলে Name, ID আর Section মিলিয়ে নিন। ভুল থাকলে ঠিক করে দিন (একই ID দুজনের আছে কি না খেয়াল রাখবেন)।
  3. Status Approved করুন আর দরকারি option টিক দিন:
    • Section user (যেমন Commissioning): নিজের টিম, যেমন "Commissioning Team", আর যা যা লাগবে (Component Selection, Calculations, Troubleshooting ইত্যাদি)।
    • R&I user: যে টিমগুলোর রিকোয়েস্ট সে সামলাবে সেগুলো (যেমন Commissioning Team, After Sales Team), সাথে R&I Team Activity বা Project Manager লাগলে সেগুলোও।
    • Forward করা যাবে শুধু সেই R&I user-কে, যার ওই টিমে টিক আছে।
  4. Save user & access চাপুন। ইউজার পরের লগইনে নতুন মেনু পাবে।
